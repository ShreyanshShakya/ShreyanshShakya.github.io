> **Title:** *Speech Emotion Recognition: A Human-Centric Framework with Enhanced Data Augmentation and Lightweight CNN*

Speech Emotion Recognition (SER) aims to classify emotional states from speech. This project focused on building a **lightweight CNN-based emotion classification system**, with audio preprocessing and feature extraction forming an important part of the pipeline.

The work was also published at **IEEE DECoN 2025**.

## The Problem

Speech carries information beyond its words, but emotion recognition is affected by differences between speakers and recordings. A useful model therefore needs a consistent audio-processing pipeline and an architecture that can learn meaningful speech features without becoming unnecessarily large.

The project also had a practical constraint: the final trained model is documented in the project repository as being **less than 5 MB**, with the goal of keeping the system lightweight.

## Pipeline

The project follows a straightforward audio-classification workflow:

```text
Speech Audio
     ↓
Audio Preprocessing
     ↓
MFCC Feature Extraction
     ↓
Lightweight CNN
     ↓
Emotion Classification
```

## Audio Features

The system uses **Librosa** for audio processing and **MFCCs (Mel-Frequency Cepstral Coefficients)** as the primary representation for the CNN model.

MFCCs provide a compact representation of the spectral characteristics of speech and are widely used in speech-processing systems.

## CNN Architecture

The core model is a **CNN**. The project README describes the model as a lightweight architecture designed for environments with limited computational resources.

Rather than adding recurrent or attention-based components to the portfolio description, this article focuses on the architecture that is explicitly documented in the project repository: a lightweight CNN for emotion classification.

## Training

The project was trained using **Kaggle's remote GPU environment**. The repository notes that retraining the model efficiently requires a system with approximately **14 GB of GPU memory**.

The repository also includes a pretrained emotion-detection model, allowing the trained artifact to be reused without starting training from scratch.

## What I Learned

1. **Feature representation matters.** MFCCs provide a compact representation that works well with lightweight CNN architectures.
2. **Model size is an engineering constraint.** Keeping the trained model small makes deployment easier on resource-constrained systems.
3. **Preprocessing is part of the model.** In audio classification, inconsistent preprocessing can affect the quality of the features presented to the classifier.
4. **GPU resources matter during training.** Even a lightweight inference model can require substantially more memory during training.
5. **Research and engineering should agree.** The implementation and the published architecture should be described consistently rather than mixing experimental variants into the final system description.

## Future Work

Potential directions include stronger noise robustness, improved cross-speaker generalization, alternative audio representations, and evaluation of newer speech representation models.
